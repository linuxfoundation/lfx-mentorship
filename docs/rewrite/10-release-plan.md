# Mentorship Rewrite — 10: Release Plan

Status: Final. Release window: **Monday 2026-10-26, 10:45 PM PT** to Tuesday morning PT, with the go-live decision at about **7 to 8 AM PT on Tuesday 2026-10-27**.
Related: [08 runbook](./08-prod-migration-runbook.md) holds the commands; this page holds the order and the owners.

## Approach

1. **Test on prod data now.** Import legacy prod data into the new prod and test there while legacy keeps serving users. Email reaches only `EMAIL_ALLOWED_RECIPIENTS`, and Self Serve shows Mentorship only to testers (LaunchDarkly `mentorship-enabled`).
2. **Release with a few hours of downtime.** Close legacy, wipe the test data, run a fresh full import, verify, then send everyone to the new site. The import itself took about 16 minutes on the smoke run; the window is the file copy, verification and the FGA drain for applications and programs on top: about 2 to 2.5 hours. Task permissions keep draining for about 3.5 hours after go-live; existing tasks already have theirs.

## Release day

Times are PT; commands are in runbook 08. Go-live waits for the application and program permissions to drain, not the tasks: see "Import and outbox-drain time measured" above. With the import at 11:15 PM, both drains finish before the morning.

- [ ] **10:45 PM Freeze legacy** (Michal): post the downtime notice in #mentorship_admins and #lfx-mentorship-rewrite; tag `jobspring` `v1.5.29` and `lfx-mentorship-upgrade` `v1.5.6` and approve both deploys; check the legacy API answers 503 and the legacy site shows the maintenance page; wait 15 min for running cron jobs
- [ ] **11:00 PM Migrate** (Michal and Lewis on [Zoom](https://linuxfoundation.slack.com/archives/C0BK7NQ3Q6Q/p1793039914924399)), runbook Phases 2 to 4, in this order:
  - [ ] Start the migration pod (Phase 2): fresh legacy credentials, the scripts ConfigMap, the pod, the setup check. Manual, about 10 min
  - [ ] Copy the files added since the test import (Phase 3, about 20 min); it writes the manifest the import needs
  - [ ] `TRUNCATE` the `mentorship` schema (Phase 4, step 5), on Michal's explicit go
  - [ ] 11:15 PM: import without `--test-run`, with `USER_FIXES` if needed (16 min). The FGA drain starts at commit: applications and programs done by about 12:45 AM, tasks by about 4:30 AM
- [ ] **Overnight** (Lewis): sanity check in PROD: run the migration validation script, `verify_migration.py`, and `verify_objects.py`; both must end with no mismatches (Phase 5, steps 4 and 5), the UI spot checks (step 6), and the PROD, migrated-data and legacy-redirect checks of the [E2E test plan](https://github.com/linuxfoundation/lfx-mentorship/pull/356) (sections 9 to 11). Watch the drain: no pending `mentorship_application` or `mentorship_program` rows in `fga_outbox`, no `dead_letter`, the fga-sync backlog, backend errors, RDS CPU; don't raise the rate.
- [ ] **7 to 8 AM Go/no-go** (Michal, Lewis): Phase 6, step 1. No-go: unfreeze legacy, stop
- [ ] **Email to everyone** (Michal): remove `EMAIL_ALLOWED_RECIPIENTS` in lfx-v2-argocd, wait for the rollout. The rollout re-runs the approver sync Job; check its log lists every approver (all of them are legacy users, so the import recreates them)
- [ ] **Self Serve to everyone** (Michal): `mentorship-enabled` on for all users
- [ ] **About 8 AM Redirect the legacy host** (Antonia, DevOps): ping her in the thread, she merges [lfx-v2-opentofu#274](https://github.com/linuxfoundation/lfx-v2-opentofu/pull/274). - [ ] **Watch the system** (Michal, Sameh): backend errors in Datadog Logs, the fga-sync backlog and `dead_letter`, and the first hours of real traffic

**Rollback:** clean until "Self Serve to everyone". After that, fix forward.
